📧 Configurar info@amgdl.com amb Cloudflare

DNS a Cloudflare · objectiu: que info@amgdl.com arribi a amgdigitalitzacions@gmail.com · document intern AMG

Estat actual (verificat)

  • amgdl.com → cap MX → info@amgdl.com rebota, no arriba enlloc.
  • Nameservers a Cloudflare ✅ · DMARC de Brevo ✅ · cap SPF propi (només brevo-code).
  • inbound.amgdl.com → té MX a Brevo i Cloudflare alhora (ambigu, a netejar — Part 2).

Part 1 · Activar Email Routing (info@ → Gmail)

  1. Entra a dash.cloudflare.com → tria la zona amgdl.com.
  2. Menú esquerre → Email → Email Routing → Get started / Enable.
  3. Cloudflare et proposarà afegir els registres DNS necessaris. Accepta'ls (botó «Add records»). Afegirà:
    TipusNomValor
    MXamgdl.comroute1.mx.cloudflare.net (prio 1)
    MXamgdl.comroute2.mx.cloudflare.net (prio 2)
    MXamgdl.comroute3.mx.cloudflare.net (prio 3)
    TXT (SPF)amgdl.comv=spf1 include:_spf.mx.cloudflare.net ~all
  4. Destination addresses → Add destination → amgdigitalitzacions@gmail.com → Cloudflare hi envia un correu de verificació → obre el Gmail i clica el link (queda ✅ Verified).
  5. Routing rules → Create address → escriu info@amgdl.com → Action: Send to → amgdigitalitzacions@gmail.com → Save.
  6. (Recomanat) Catch-all address → activa'l → Send to amgdigitalitzacions@gmail.com. Així res que arribi a qualsevol @amgdl.com es perd.
Nota SPF: si algun dia envies correu des de @amgdl.com amb Brevo, canvia l'SPF per incloure Brevo:
v=spf1 include:spf.brevo.com include:_spf.mx.cloudflare.net ~all (un sol registre SPF, mai dos).
Prova: espera 5-10 min i envia un correu a info@amgdl.com des d'un altre compte → t'ha d'arribar al Gmail. Ja pots contestar (per respondre «com a info@», configura «Send mail as» al Gmail més endavant).

Part 2 · Netejar el doble MX de inbound.amgdl.com

Aquest subdomini és el camí del bot (correu entrant dels tenants → webhook de la plataforma). Ara té dos proveïdors alhora, cosa que el fa poc fiable. Deixa'n només un.

  1. A Cloudflare → DNS → Records, filtra per inbound.
  2. Veuràs 4 MX a inbound.amgdl.com: un de Brevo (mxrecord-0.inbound.brevo.com) i tres de Cloudflare (route1/2/3.mx.cloudflare.net).
  3. La plataforma usa Brevo Inbound (l'stack és Brevo). Per tant: esborra els 3 MX de route*.mx.cloudflare.net de inbound.amgdl.com i deixa només el de Brevo.
  4. Verifica a Brevo → Transactional → Inbound parsing que el domini inbound.amgdl.com reenvia al webhook:
    https://api.amgdl.com/api/v1/agents/email/inbound
Compte: en activar Email Routing a la zona (Part 1), assegura't que Cloudflare no toqui els MX de inbound.amgdl.com (ha de seguir apuntant a Brevo). Si Cloudflare hi torna a posar els seus MX, torna'ls a treure.

✅ Verificació final (des del terminal)

  • dig +short MX amgdl.com → ha de sortir route1/2/3.mx.cloudflare.net.
  • dig +short MX inbound.amgdl.com → només mxrecord-0.inbound.brevo.com.
  • Correu de prova a info@amgdl.com → arriba al Gmail.
El bot i info@: amb això, info@ el llegeix una persona (Gmail). Si algun dia vols que el bot contesti info@, cal encaminar-lo al webhook (MX de amgdl.com cap a Brevo inbound) i mapar l'adreça al tenant d'AMG — més feina i no necessari per a un info@ general.
