🟦 Meta — Instagram + Facebook (connexió manual per token)

A la plataforma, la publicació a IG/FB no fa OAuth: l'admin enganxa un Page Access Token amb els permisos correctes a la fitxa del tenant. La Meta App només serveix per generar aquest token amb els permisos aprovats.

Pas 1 · La Meta App (developers.facebook.com)

  1. Obre la teva App a developers.facebook.com (ja tens App Secret configurat; assegura't també de tenir l'App ID a mà).
  2. Afegeix els productes: Facebook Login i Instagram Graph API.
  3. Fes la Business Verification del teu negoci (Business Settings → Security Center) si no està feta.

Pas 2 · App Review — permisos a demanar

  • pages_show_list · pages_read_engagement
  • pages_manage_posts — publicar a Facebook
  • instagram_basic · instagram_content_publish — publicar a Instagram
  • business_management
  • A App Review → Permissions and Features, sol·licita cada permís.
  • Adjunta un screencast del cas d'ús: a la fitxa del tenant enganxes el token → publiques un post de prova.
  • Text del cas d'ús: «SaaS que gestiona la presència digital de comerços locals de Mallorca; publiquem al seu Instagram/Facebook amb el seu consentiment.»
  • Passa l'App a mode Live.
Coll d'ampolla: l'App Review de Meta triga dies o setmanes. Engega-ho ja. Fins que no estigui aprovat, no podràs generar un token amb aquests permisos.

Pas 3 · Generar el Page Access Token del client

  1. El client t'ha de fer admin de la seva Pàgina de Facebook (i tenir el compte d'Instagram Business vinculat a la Pàgina).
  2. La via neta i estable: Business Settings → Users → System Users → crea un System User → assigna-li la Pàgina → Generate Token amb els permisos de dalt. (Alternativa ràpida per provar: Graph API Explorer, però el token dura poc.)
  3. Anota: Facebook Page ID, Instagram Business Account ID i el Page Access Token (llarga durada).

Pas 4 · Enganxar-ho al portal

  • Portal → /portal/admin/tenants/[id]/social → omple:
    • Facebook Page ID
    • Instagram Account ID
    • Page Access Token (+ data de caducitat si escau)
  • Desa. A partir d'aquí, el Content Planner publica a IG i FB.

🟨 Google Business — post + galeria (OAuth)

Aquí sí que és OAuth: falten les credencials GOOGLE_OAUTH_CLIENT_ID/_SECRET. Un cop posades, cada tenant connecta el seu Google Business amb un clic.

Pas 1 · Credencials a Google Cloud (console.cloud.google.com)

  1. Crea (o reutilitza) un projecte.
  2. APIs & Services → Library: activa la Business Profile API (i «My Business Account Management» / «Business Information» si apareixen).
  3. OAuth consent screen: tipus External. Afegeix l'scope sensible https://www.googleapis.com/auth/business.manage.
    Aquest scope és sensible/restringit: Google exigeix verificació de l'app (justificació d'ús, potser vídeo). Pot trigar. Mentre no es verifiqui, funciona en mode Testing amb usuaris de prova afegits.
  4. Credentials → Create OAuth client ID → Web application. Redirect URI autoritzat:
    https://api.amgdl.com/api/v1/google/callback
  5. Copia el Client ID i el Client Secret.

Pas 2 · Posar les credencials a la plataforma

  • Portal → Config del sistema → omple:
    • GOOGLE_OAUTH_CLIENT_ID
    • GOOGLE_OAUTH_CLIENT_SECRET

Pas 3 · Connectar cada tenant

  1. A la fitxa del tenant (integracions Google), el tenant/admin fa Connectar Google (mòdul business → scope business.manage).
  2. Selecciona la ubicació del negoci (es desa com businessLocationId).
  3. A partir d'aquí, el Content Planner publica com a post al perfil i, amb el canal Galeria Google, afegeix la foto a la galeria permanent.

✅ Verificació final

  1. Crea i activa un pla de contingut per a un tenant amb Telegram enllaçat (/portal/admin/tenants/[id]/content-plan).
  2. Envia una foto pel Telegram del tenant → arriba el caption → confirma ✅.
  3. Comprova que apareix a Instagram, Facebook, i a Google (post + galeria).
Recorda: connectar les xarxes és un one-time per tenant (un clic Google + enganxar el token Meta). La feina mensual (crear i publicar contingut) l'automatitza el Content Planner: el tenant només envia la foto. Mentre no hi hagi connexió, el flux funciona fins a l'aprovació i el tenant rep l'avís de connectar.
